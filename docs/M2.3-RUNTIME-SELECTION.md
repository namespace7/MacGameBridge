# M2.3 — Runtime Selection Engine

## Overview

The Runtime Selection Engine (`RuntimeSelector`) is a deterministic, provider-independent selector that consumes discovered and validated `ProviderInstallation` arrays (from M2.2 `RuntimeScanner`) and produces explainable selection results. Selection is **read-only** — it does not launch, install, modify, or execute any runtime.

## Design Goals

1. **Deterministic** — Same inputs always produce the same output.
2. **Explainable** — Every result carries structured evaluation reasons for each candidate.
3. **Safe** — Never silently substitutes an installation when the user explicitly requested a specific one.
4. **Architecture-aware** — Evaluates runtime architecture against host capabilities, including Rosetta availability.
5. **Pure and testable** — No filesystem, process execution, or CLI coupling.

## Key Models

### `RuntimeSelectionPolicy`
Defines how the selector chooses among available installations:

- **`automatic`** — Rank all candidates and pick the best validated, compatible installation.
- **`preferProvider(RuntimeProviderID)`** — Prefer candidates from a specific provider; fall back only if `allowFallback` is true.
- **`exactInstallation(String)`** — Require an exact installation by ID; **never** falls back.

### `RuntimeSelectionRequest`
Contextual host information for architecture evaluation. This parameter is **required** — there is no default, ensuring the caller must provide explicit architecture and Rosetta information.

| Field | Type | Description |
|-------|------|-------------|
| `hostArchitecture` | `RuntimeArchitecture` | Host CPU architecture (typically `arm64` or `x86_64`). When set to `unknown`, all candidates are rejected — no compatibility can be positively established. |
| `rosettaAvailable` | `Bool` | Whether Rosetta 2 is available on Apple Silicon. Must be explicitly confirmed; never silently assumed. |
| `allowFallback` | `Bool` | Whether fallback is permitted when preferred provider fails |

### `RuntimeSelectionRejection`
Structured, non-ambiguous rejection reason (enum):

| Case | Description |
|------|-------------|
| `notValidated(RuntimeInstallationStatus)` | Installation status is not `validated` |
| `unknownArchitecture` | Architecture could not be determined |
| `rosettaNotAvailable` | x86_64 runtime on Apple Silicon without Rosetta |
| `architectureIncompatible(String)` | Architecture incompatible with host |
| `notPreferredProvider(RuntimeProviderID)` | Not from the preferred provider |
| `lowerRanked(selectedID:)` | Lower-ranked than the selected installation |
| `notExactInstallation` | Not the requested exact installation |
| `installationNotFound(String)` | Requested exact installation ID was not found |
| `noCandidates` | No candidates available |

### `RuntimeCandidateEvaluation`
Evaluation result for a single candidate:
- `installation: ProviderInstallation`
- `accepted: Bool`
- `rejection: RuntimeSelectionRejection?`

### `RuntimeSelector.appleSiliconRequest(rosettaAvailable:)`
Factory method returning a properly configured request for Apple Silicon. The caller **must** provide the actual Rosetta availability — the method does not default to `true`.

### `RuntimeSelector.intelRequest`
A pre-built request for Intel Mac hosts (`x86_64`, no Rosetta).

### `RuntimeSelectionResult`
Complete, explainable result:
- `selected: ProviderInstallation?`
- `selectionReason: String`
- `evaluations: [RuntimeCandidateEvaluation]`
- `failure: RuntimeSelectionRejection?`
- `usedFallback: Bool`

## Selection Rules (in order)

1. **Exact pin** — An exact installation pin takes precedence over every other preference.
2. **No silent substitution** — If the pinned installation is missing or invalid, return a failure. Never silently substitute another installation.
3. **Provider preference** — A preferred provider ranks ahead of other providers.
4. **Fallback only when allowed** — If provider preference cannot be satisfied, fallback is permitted only when the request explicitly allows it.
5. **Validated only** — Never select an installation whose status is not `validated`.
6. **Known architecture required** — Reject unknown architecture.
7. **Architecture compatibility**:
   - ARM64 runtime on ARM64 host: compatible.
   - x86_64 runtime on Apple Silicon: compatible only when Rosetta is available.
   - Universal runtime: compatible if it contains a usable host or translated slice.
   - **Unknown host**: When `hostArchitecture` is `.unknown`, every candidate is rejected.
8. **Explicit Rosetta** — Never assume Rosetta is available. Use the value in the request.
9. **Explain rejection** — Return a clear rejection reason for every rejected candidate.
10. **Deterministic tie-breaking** — Must not depend on filesystem enumeration order.

## Ranking Rules (Automatic Mode)

Candidates are sorted by these criteria in order:

| Priority | Criterion | Order |
|----------|-----------|-------|
| 1 | Status | `validated` > `detected` > `notDetected` |
| 2 | Architecture | `arm64` > `universal` > `x86_64` > `unknown` |
| 3 | Provider | CrossOver > Wine > Whisky > Sikarugir |
| 4 | ID | Lexicographic (ascending) |

## Safety Guarantees

- **`exactInstallation`** never falls back, regardless of `allowFallback`. If the exact ID is not found, not validated, or architecture-incompatible, the result has `selected == nil` and `usedFallback == false`.
- **`preferProvider`** falls back only when `allowFallback` is `true` and the preferred provider has zero valid candidates.
- **`automatic`** never sets `usedFallback` to `true`.
- Selection always requires `validated` status — `detected` or `notDetected` installations are rejected.

## Architecture Compatibility

| Runtime Arch | Host Arch | Rosetta | Compatible |
|-------------|-----------|---------|------------|
| `arm64` | `arm64` | N/A | Yes |
| `arm64` | `x86_64` | N/A | No |
| `x86_64` | `x86_64` | N/A | Yes |
| `x86_64` | `arm64` | Available | Yes |
| `x86_64` | `arm64` | Not available | No |
| `universal` | `arm64` | N/A | Yes |
| `universal` | `x86_64` | N/A | Yes |
| any | `unknown` | any | No — host architecture is unknown, no compatibility can be positively established |
| `unknown` | any | N/A | No |

## Dependencies

The selector depends only on M2.2 types:
- `ProviderInstallation` (from `RuntimeInstallation.swift`)
- `RuntimeInstallationStatus`
- `RuntimeArchitecture`
- `RuntimeProviderID`

No new dependencies in `Package.swift` are required.

## Limitations

- Selection does not prove game compatibility or successful runtime execution.
- The selector does not detect Rosetta availability; it must be provided in the request.
- When `hostArchitecture` is `.unknown`, all candidates are unconditionally rejected.
- Architecture compatibility is evaluated strictly; a universal binary with only an x86_64 slice on Apple Silicon without Rosetta is rejected.
- The `preferProvider` policy with `allowFallback: false` returns a failure rejection instead of silently switching providers.
- The `RuntimeSelectionRequest` parameter is required — there is no default that silently assumes Rosetta is available.

## Future Integration

- Game launch workflows will call `RuntimeSelector.select(from:policy:request:)` with the scanner's output and host information.
- ROSETTA detection can be wired to `sysctl.proc_translated` or `softwareupdate --list` in a future integration layer.
